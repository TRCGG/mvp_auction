# 실시간 경매

팀장들이 각자 화면에서 직접 입찰하는 경매 진행 도구입니다.
Cloudflare Workers 무료 플랜에서 동작합니다.

## 배포

```bash
npm install
npx wrangler login
npx wrangler secret put ADMIN_PASSWORD   # 관리자 비밀번호를 정합니다
npx wrangler deploy
```

`ADMIN_PASSWORD`를 설정하지 않으면 관리자 로그인이 되지 않아 경매방을 만들 수 없습니다.
나중에 바꾸려면 같은 명령을 다시 실행하세요. 로컬 테스트용으로는
프로젝트 폴더에 `.dev.vars` 파일을 만들고 `ADMIN_PASSWORD="원하는값"` 을 적으면 됩니다.
(`.dev.vars`는 절대 커밋하지 마세요.)

배포가 끝나면 `https://lol-auction.<계정이름>.workers.dev` 주소가 나옵니다.
이름을 바꾸려면 `wrangler.jsonc`의 `name`을 수정하세요.

로컬에서 먼저 확인하려면:

```bash
npx wrangler dev
```

## 참가자 명단

같이 받은 `참가자_명단_양식.xlsx`를 클랜원들에게 돌리세요.
닉네임 · 태그 · 주포지션 · 부포지션 · 솔랭 티어 · 주챔프 3개를 적는 양식이고,
포지션과 티어는 목록에서 고르게 되어 있습니다.

받은 파일을 경매 설정 화면에 끌어다 놓으면 참가자 목록이 자동으로 들어갑니다.
포지션별 인원과 닉네임 중복도 그 자리에서 확인할 수 있습니다.

- 열 제목으로 찾기 때문에 열 순서가 바뀌어도 읽힙니다
- 닉네임이 빈 줄과 `(예시)`로 시작하는 줄은 건너뜁니다
- `정글`, `원딜`, `서폿`, `탑`, `미드` 같은 한글 표기도 인식합니다
- **A열에는 참가자 닉네임 외에 아무것도 적지 마세요.** 메모를 적으면 참가자로 읽힙니다

엑셀이 번거로우면 설정 화면의 '엑셀 없이 직접 입력하기'에서
`닉네임, 포지션, 티어` 형태로 붙여넣어도 됩니다.

## 진행 순서

1. 배포된 주소에서 **관리자** → 비밀번호로 로그인
2. **새 경매방 만들기** → 규칙과 팀장을 입력하고 참가자 엑셀을 올린 뒤 생성
3. 나오는 링크 목록에서 **각 팀장에게 자기 링크만** 개인 메시지로 전달
4. **진행자로 입장** 해서 매물을 올리면 팀장들이 각자 화면에서 입찰
5. 제한 시간이 끝나면 최고 입찰자에게 자동 낙찰

## 관리자 화면

주소 뒤에 `#/admin` 을 붙이거나 첫 화면의 관리자 버튼으로 들어갑니다.

- 만든 경매방 목록과 상태(대기 · 진행 중 · 종료), 낙찰 진행률, 현재 접속 인원
- **링크 다시 보기** — 팀장 링크를 잃어버려도 여기서 다시 꺼낼 수 있습니다
- 진행자로 바로 입장
- 방 삭제 (진행 기록과 링크가 사라지고 접속자는 연결이 끊깁니다)

로그인 세션은 12시간 유지되며 브라우저를 닫으면 사라집니다.

## 규칙

- 팀장은 자기 팀으로만 입찰할 수 있고, 진행자는 입찰할 수 없습니다
- 입찰은 현재 최고가 + 최소 단위 이상이어야 합니다
- 이미 최고 입찰 중이면 자기 자신에게 덧입찰할 수 없습니다
- 입찰 한도 = 잔여 포인트 − (남은 자리 − 1) × 최소 단위
  마지막 자리까지 최소 금액으로는 채울 수 있게 자동으로 상한이 걸립니다
- 입찰이 들어올 때마다 제한 시간이 다시 채워집니다
- 시간이 다 되면 자동 낙찰, 입찰이 없으면 유찰
- 진행자는 즉시 낙찰, 유찰, 일시정지, 되돌리기를 쓸 수 있습니다
- 되돌리기는 직전 매물을 올리기 전 상태로 되돌립니다

## 무료 플랜 한도

Durable Objects 무료 한도는 하루 요청 10만 건, 지속시간 13,000 GB-초입니다.
WebSocket 메시지는 20건이 요청 1건으로 계산됩니다.

팀장 6명 + 관전자 몇 명이 두 시간 경매하는 경우 지속시간은 900 GB-초 안팎,
메시지는 수천 건이라 요청 수백 건 수준입니다. 매일 열어도 한도에 닿지 않습니다.

## 주의

- 관리자 로그인은 한 IP에서 8회 실패하면 10분 잠깁니다.
  잠긴 동안은 올바른 비밀번호도 거부되니 오타에 주의하세요. IP별로 따로 셉니다.
- 링크가 곧 신분입니다. 남의 링크를 받으면 그 팀으로 입찰할 수 있으니
  단톡방에 전체 목록을 뿌리지 마세요.
- 방 설정은 시작 전(대기 상태)에는 방 안의 **방 설정 수정** 버튼으로 전부 바꿀 수 있습니다.
  명단이 유지된 팀의 링크는 그대로 유효하고, 팀장을 삭제하면 그 팀 링크만 무효화됩니다.
  시작한 뒤에는 초기화로 대기 상태로 돌아간 다음에만 수정할 수 있습니다.
- 관리자 비밀번호는 이 도구의 유일한 관문입니다. 충분히 길게 잡으세요.

## 구조

```
src/index.js      Worker 라우팅 + 관리자 인증
                  AuctionRoom  경매방 하나의 권위 상태
                  Registry     만든 방의 목록 (DO는 목록 조회가 없어서 따로 둡니다)
public/index.html 클라이언트 (관리자 · 설정 · 경매 화면)
wrangler.jsonc    무료 플랜용 SQLite Durable Object 설정
```

관리자 토큰은 `ADMIN_PASSWORD`를 키로 한 HMAC-SHA256 서명이라
서버에 세션을 따로 저장하지 않습니다. 비밀번호를 바꾸면 기존 토큰이 전부 무효가 됩니다.

남용을 막기 위한 장치가 몇 가지 들어 있습니다.

- WebSocket 메시지는 4KB를 넘으면 파싱하지 않고 거부합니다
- 한 접속에서 2초에 12건까지만 받습니다 (연타·스크립트 폭주 차단)
- 방 코드로는 대회 이름만 알 수 있고 참가 팀 구성은 나오지 않습니다
- 되돌리기 기록은 한 칸씩 따로 저장합니다.
  한 덩어리로 두면 매물을 올릴 때마다 스택 전체를 다시 써야 해서
  참가자 200명 기준 매번 1MB씩 쓰게 됩니다.

상태는 전부 서버가 들고 있고 클라이언트는 받아서 그리기만 합니다.
그래서 새로고침하거나 연결이 끊겨도 다시 접속하면 현재 상태를 그대로 받습니다.
Durable Object는 단일 스레드로 동작하므로 동시 입찰이 들어와도
먼저 도착한 쪽만 성립하고 나머지는 거부됩니다.
